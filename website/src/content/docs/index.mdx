## What you get

<CardGrid>
	<Card title="It returns" icon="approve-check">
		`GracefulStop` returns the stops' errors instead of calling `os.Exit`, so `main` picks the exit status
		and its deferred calls run.
	</Card>
	<Card title="One deadline" icon="seti:clock">
		The stops share a context that is done a set time after the shutdown starts. Pass `srv.Shutdown` as it is.
	</Card>
	<Card title="In order, every error kept" icon="list-format">
		Stops run one after another, in the order you pass them. Every one is called, and their errors come back

## From the first signal to the last stop

<div class="landing-lead">
	`GracefulStop` blocks your `main` until it's time to stop, then runs your stops on the same goroutine and
	returns.
</div>

<Steps>

1. **It waits** for SIGINT, SIGTERM or SIGHUP, or for the context you passed to be done.

2. **It runs your stops**, one after another, with a context that is done `timeout` later.
   Each gets the same deadline; each should return once it passes.

3. **A second signal ends the process** at once, with exit status 1. The stops don't finish and deferred calls
   don't run.

4. **It returns** the stops' errors joined, or nil, and stops listening for signals.
   `main` decides what to do with them.

</Steps>

## Coming from v1

<div class="landing-lead">
	v1 ran one function and called `os.Exit(0)`. v2 hands your stops a deadline, returns their errors, and leaves the
	exit to you.
</div>

<div class="compare">

```go title="v1"
shutdown.GracefulStop(func() {
	ctx, cancel := context.WithTimeout(
		context.Background(), 10*time.Second)
	defer cancel()

	if err := srv.Shutdown(ctx); err != nil {
		log.Printf("shutdown: %v", err)
	}
})
// never reached: v1 calls os.Exit(0)
```

```go title="v2"
err := shutdown.GracefulStop(
	context.Background(),
	10*time.Second,
	srv.Shutdown,
)
if err != nil {
	log.Fatalf("shutdown: %v", err)
}
```
